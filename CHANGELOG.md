# Changelog

## v3.7.0 - 2026-08-25

### Added

- `START_HERE.md` mandatory bootstrap and machine-readable bootstrap-release evidence.

### Fixed

- The fixed execution contract no longer depends on the user resending long instructions on a new computer or task.

## v3.6.0 - 2026-08-25

### Added

- A non-bypassable direct-support route for named core conversion products. `direct_supported` now requires a direct-solution heading, an article-visible current official feature URL, product scenarios, workflow, constraint, and CTA.
- Product-route regression coverage for direct support, adjacent authorized support, and no truthful route.

### Fixed

- Preflight now fails if a product is classified `direct_supported` but its evidence retains an `ultra_tips` object or its article still routes that product through `Ultra Tips`.
- A `no_truthful_route` classification is now explicitly release-blocking pending an approved alternative; it can no longer quietly pass as a completed product decision.

## v3.5.2 - 2026-08-25

### Added

- A mandatory Boundary-sensitive core conversion (Ultra Tips) route for a named core product that cannot perform the article's primary task but has a verified lawful adjacent use.
- Required product-route evidence: primary-task support, exact Ultra Tips H2, boundary wording, supported route, 4–6 steps, 3 touchpoints, status-safe CTA, and mapped product visual.

### Fixed

- Prevents core conversion products from being reduced to an exclusion-only paragraph after an availability or capability check.
- Preflight now blocks missing or weak Ultra Tips modules and blocks fabricated routes when no truthful adjacent use exists.

## v3.5.1 - 2026-08-25

### Changed

- Adds the minimal-instruction contract to the workflow entry points: the source DOCX, canonical keyword workbook, and one standard command invoke the full v3.5 delivery contract.
- States that any supplied reference article is quality-only and can never prescribe the target article's structure.

## v3.5.0 - 2026-08-25

### Added

- Content-economy audit and a 110%-of-source expansion justification gate.
- Mandatory heading-role map for every H1/H2/H3, distinguishing keyword-bearing headings from action-led steps.
- All-H2 visual-scope rule for “every section” requests, including Sources unless explicitly exempted.
- Deduplicated, claim-linked source-record contract with official URL and current verification date.
- Live product availability, beta/demo/coming-soon, and CTA-suitability evidence.

### Fixed

- Prevents duplicate Quick Answer/chooser/verdict guidance, repeated product boundaries, and duplicate source lists from being treated as retained depth.
- Prevents grammatical heading damage caused by forcing exact keyword strings into titles.
- Prevents a hand-shortened visual-section list from silently excluding Sources or another final H2.

## v3.4.0 - 2026-08-24

### Added

- A non-bypassable named final human QA record covering content, keywords, products, visuals, sources, rendered pages, document hygiene, and package purity.
- Exact release-file manifest checking, actual source/final word-count regression, and DOCX comments/tracked-changes detection.

### Changed

- Rendering is now an absolute publication gate: without rendered-page review, the only permitted status is `Structurally verified - visual QA pending`.

## v3.3.0 - 2026-08-24

### Added

- Mandatory dated SERP research and a structure plan that maps reader decisions to evidence, preserved source assets, keyword clusters, product roles, and visual jobs.
- An 80–90% effective-information retention target for Optimization Mode, with explicit authorization required below 80%.
- A per-use visual-evidence contract covering reader scenario, concrete scene, style, rights, true Alt, caption, exact insertion point, and rendered QA.
- Machine-readable release evidence and stronger preflight checks for generic keyword exceptions, incomplete product maps, missing SERP evidence, weak visual maps, and mixed release folders.

### Changed

- A reference article is now explicitly a quality benchmark only; it cannot prescribe a target article's outline.
- Yellow highlights now prove reader-facing editorial optimizations, not query lists or artificial coverage sentences.

## v3.2.0 - 2026-08-24

### Added

- Release-lock gate ledger and a preflight validator for article structure, keyword evidence, image metadata, assets, and clean/marked integrity.
- Canonical keyword-workbook sheet rule, strict Top-20 disposition record, and named exception policy.
- Run-safe marked-copy rule that prevents paragraph rebuilds from duplicating text or damaging rich content.
- Explicit per-section visual coverage rule for requests that require visuals in every section.

### Fixed

- Closed the gap where a workflow could be read but an incomplete draft could still be handed off as a review result.
- Clarified that keyword highlights must identify natural in-article optimization, never a coverage table or grouped query dump.

## v3.1.0 - 2026-08-21

### Added

- Content Preservation Audit, Rewrite Boundary Rule, and Content Retention QA.
- Product Portfolio, Placement & Conversion Review for multiple products and solution types.
- Visual Asset Standard requiring real, embedded, packaged assets instead of image plans.
- Delivery Acceptance Standard that distinguishes a publication-ready article from a review memo, outline, or asset plan.
- Section-level keyword distribution audit and typo/low-quality keyword exception policy.
- Templates for source-asset audit, keyword map, product map, visual asset map, and final delivery checklist.

### Changed

- Default mode is now Optimization Mode: preserve -> improve -> expand.
- Product review now verifies claims without stripping legitimate product conversion content.
- Final QA now includes render, source-asset regression, visual, table, keyword, product, and delivery checks.

### Removed

- The implicit assumption that shorter output is automatically better.
- The implicit assumption that one featured product represents the whole product-review workflow.
