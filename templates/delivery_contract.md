## Markup and QA rule

- Yellow highlights: marked review copy only / both copies (explicit choice).
- Highlighted strings: Top 20 exact terms / approved list: 
- Clean and marked copies must have text-identical content after highlight removal: Yes.
- Render gate: required / fallback label if unavailable.
- Reference article usage: quality benchmark only / not a structural template.
- Content-economy rule: one primary owner per reader decision; explain any final word-count expansion above 110% of source.
- Heading-role map required: Yes. Core H1/H2 and FAQ/product H3 keyword roles; action H3s may inherit parent intent.
- Product availability check required immediately before release: Yes. Record current state and CTA-safe action.
- Core conversion product route check: for each named core product, record the exact primary task, current official feature URL, verification date, and primary-task support (`Direct supported` / `Adjacent authorized route` / `No truthful route`). A direct-supported core product requires a named direct-solution H2, article-visible feature URL, 3 best-for scenarios, workflow, limitation, and CTA; it must not have Ultra Tips/adjacent/not-supported residue. An adjacent authorized route requires the Ultra Tips H2, 3 best-for scenarios, not-for route, 4–6 steps, 3 touchpoints, one mapped product visual, and a status-safe CTA. No truthful route blocks release pending an approved alternative.
- Sources: one deduplicated claim-linked list; official URL and verification date required for version-sensitive claims.
